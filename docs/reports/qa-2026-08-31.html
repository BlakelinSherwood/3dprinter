The audit — what it found

Six specialist reviewers read every part of the system (safety chain, server, interface, slicing, mesh pipeline, docs); every serious claim went to an adversarial referee before counting. 22 findings survived. The two that mattered most:

critical fixed + tested

The volume checker could be fooled by "relative" movement

Before any file is printable it must pass a check: temperatures in range, and every movement inside the printer's 220×220×250 mm box. But G-code has two movement modes — "go to Z200" and "go up by 200" — and the checker only understood the first. A file could climb past the ceiling in small "up by" steps and still pass. Our own printer's standard ending sequence uses that mode, so the checker was mis-reading every file's final moves.

Now: the checker tracks the physical position through every mode, datum reset, and homing command. A file that tries to sneak past the ceiling fails loudly. Thirteen attack files — including ones the referee invented to beat my first fix — are all caught, and your real sliced files still pass.

critical fixed + tested

A timing gap between "check the file" and "send the file"

Uploading re-checks the G-code, then sends it. But those were two separate steps reading from the same spot on disk — and a slice happening at the same moment could swap in new, unchecked G-code between them. Single click-path use never hits this, but the safety rule is supposed to hold no matter what.

Now: slicing and uploading take turns (never interleave), sliced G-code only lands at its final location after its check passes, and every file carries a marker saying which material it was checked for — no marker, no upload.

Also confirmed and fixed

  • Auto-orient's rotation was inverted (the worst-case version of "backwards") — fixed and physics-verified.
  • "a 1/4 inch hole" was being read as "shrink to quarter scale" — dimensions and hobby scales are now told apart (11-case test).
  • Click-a-spot editing aimed at the wrong place on scaled or rotated models — clicks now map back through the full display transform.
  • Any web page in a browser on this Mac could have poked the studio's controls (including deleting files from the printer queue) — cross-origin requests are refused now, and request names can't escape the studio's folders.
  • Several double-click / mid-operation races in the interface — a double-clicked "Build 3D" would have paid Tripo twice.
  • The docs described the system as it was before the Raspberry Pi move; the relay everything depends on was documented only in a commit message. README and handoff docs now describe reality.

The audit was audited

round two

Six referees tried to break the fixes — and partly succeeded

Rather than trust my own patches at 1am, I sent a second team to attack them. They confirmed two fixes outright (the timing gap, the orientation math) and broke three others in ways that mattered:

  • My first volume-checker fix could still be fooled by a "datum reset" trick (G92) — and missed the decimal style (Z.4) our own slicer actually writes. Both closed.
  • My name-validation was too strict: it would have rejected everyday files like part (1).stl — a regression you'd have hit on your first download this morning. Relaxed to sanitize instead of refuse.
  • Three interface entry points could still sneak past the busy-lock. Guarded.

Everything the referees found is fixed and re-tested. That loop — fix, attack the fix, fix again — is the reason tonight's changes deserve trust.

Known limitations, honestly

  • Generated model code runs inside the studio process. It's produced by our own guarded generator and reviewed rules, but it is not sandboxed — the right long-term fix is a separate low-privilege process.
  • The slice/upload lock protects one studio at a time; two studio instances running side-by-side could still race (don't run two).
  • Tripo multiview and Sketchfab one-click import are built and verified to their respective gates but wait on credits / a free token.
  • If a build job's final poll is lost at the exact moment of delivery, its result can be dropped (the UI recovers by regenerating).
