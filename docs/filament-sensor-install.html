Ender 3 V2 · OctoPrint on Raspberry Pi

Filament Sensor Setup

Wiring the BigTreeTech SFS V1.0 motion sensor to your Pi so a broken or stuck filament pauses the print instead of running dry all night. No printer firmware flash — it all lives on the Pi.

Pi 3 Model B+ OctoPi 1.1.0 · Bookworm OctoPrint 1.11.8 BTT SFS V1.0
⛔
The one rule that protects your Pi: the sensor's power wire goes to a 3.3V pin, never a 5V pin. The Pi's GPIO pins are not 5-volt tolerant — powering the sensor from 5V pushes 5V onto the signal wire and can permanently damage the Pi. Do all wiring with the Pi and printer powered off.

01 Identify the three wires

The SFS V1.0 has exactly three wires. Find them by the letters printed on the little sensor board — not by color (yours is a reseller bundle, so wire colors aren't guaranteed).

S
Signal (SIN) — the wire that reports filament movement.
G
Ground (GND).
V
Power (VDD) — must be connected; the sensor is active, not a plain switch.

If your cable ends in a single plastic plug, it won't fit the Pi's pins — split it into three separate female jumper leads so each wire lands on its own pin. If you have a multimeter, buzz out which bare end is S / G / V and tape a label on each.

02 Wire it to the Pi header

Pin 1 is the corner pin nearest the microSD-card slot. All three pins you need are in the first six rows, on the outer edge.

✓
Sanity check before anything else: power on just the Pi (printer can stay off). The sensor's little LED ring should light up and nothing should get warm. If anything heats up or smells, pull power — a wire is on the wrong pin.

03 Mount it on the filament path

The sensor sits inline, between the spool and the extruder, so filament passes through it on the way in.

  • Thread filament: spool → PTFE tube → sensor INLET → short tube → extruder inlet.
  • Push each PTFE tube all the way home into the push-fit couplers, or you'll get gaps that snag.
  • Fix the sensor to the frame with the two M3 screws / a printed bracket so it doesn't dangle and tug the filament.

04 Install the OctoPrint plugin

Because your Pi runs Bookworm, use the modern libgpiod plugin — the older ones need an extra fix on Bookworm. We'll do this part together.

  1. In OctoPrint: Settings (wrench) → Plugin Manager → Get More…
  2. In the “…from URL” box paste:
    https://github.com/tabahi/Octoprint-Filament-Motion-Sensor/archive/master.zip
    Click Install, then Restart OctoPrint when asked.
  3. Open the plugin's settings and set:
    Enable
    on
    GPIO pin
    17 (this is BCM numbering = physical pin 11, where wire S is)
    Distance
    start at 15–20 mm (the sensor only ticks once per 7 mm, so a bigger number avoids false pauses on slow layers)
    Timeout
    ~90 sec to start (a safety backstop; shorten later if real jams take too long to catch)
    Pause action
    leave on the default @pause
  4. In Settings → Serial Connection → “Pausing commands”, add M600 so a detected stall actually pauses (your stock firmware may not honor M600 on its own — this makes OctoPrint do the pausing).
  5. Optional but nice: in Settings → GCODE Scripts → “After print job is paused”, add a small lift-and-park so a paused nozzle doesn't melt a blob into the print: G91 / G1 Z5 F600 / G90 / G1 X10 Y10 F3000.

05 Test it safely — before trusting a real print

Three quick checks. Do all three before you leave a print unattended.

  1. Does the pin see the sensor? On the Pi's terminal run pinctrl get 17 (or raspi-gpio get 17) while you slowly push filament through the sensor by hand. The reading must flip between “lo” and “hi” as filament moves. No flip → recheck wire S on pin 11 and wire V on pin 1.
  2. Does the plugin see it? Use the plugin's “Test sensor” button and hand-feed filament — the status should change as it moves.
  3. Does it actually pause? Start a short throwaway print, let it lay a few lines, then flip open the extruder idler arm so the filament stops feeding without grinding. Within your distance/timeout the print should pause and park. Flip the arm back, reload, resume or cancel. This is fully reversible.
⚙️
If the plugin can't find the pin on your Pi 3B+: this plugin is solid but its author flags possible trouble “on RPi3 and older.” Two fallbacks — try the hviet17 fork of the same plugin, or install the older maocypher plugin and, if it logs “Failed to add edge detection,” run in the OctoPrint environment: ~/oprint/bin/pip install rpi-lgpio then restart. I'll handle whichever path we need.

Your printer's safety rules still stand: nothing prints until you say so, with you present for the first layer. This sensor is a safety net for what happens after a good start — it can't replace the first-layer check.
